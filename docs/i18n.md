# Interface translations

English is the source language. Catalogs: `apps/slint-shell/translations/<lang>/LC_MESSAGES/slint-shell.po`
for `ru`, `de`, `fr`, `es`, `it`, `pt`, `pl`, `tr`, `uk`, `cs`, `hu`, `ro`, `el`,
`hr`, `ka`, `kk`, `zh-Hans`, `zh-Hant`, `ja`, `ko`. Language names in the selector
are autonyms. Russian is maintained by hand; the others started as machine
translations and need native-speaker review (terminology, plural forms).

## How text flows

- Slint: every visible string goes through `@tr(...)`.
- Rust never formats UI text. It sends `i18n::Msg` (`Message { id, arg, count }`)
  and `Locale.text()` in `ui/i18n.slint` translates it. Technical error details
  stay in logs.
- Text outside Slint (tray, runtime messages) is registered in
  `apps/slint-shell/build-support/rust_messages.rs`; its translations are
  generated from the PO files at build time.
- Built-in macro names are passed as message ids and checked against the core
  catalog; user-defined names are never translated.
- Automatic language follows the effective locale and `LANGUAGE`; C/POSIX use
  English. A missing runtime key is logged and shows the English source.

## Adding or changing a message

Update together, in one change:

1. `src/i18n.rs` (Rust message ids) and/or `ui/i18n.slint`;
2. **every** PO catalog (Russian by hand; others may start machine-translated);
3. `build-support/rust_messages.rs` for text outside Slint.

The build fails on missing translations (including contexts and plural forms),
duplicates, empty or fuzzy entries, mismatched placeholders and missing Rust
message handlers; after compilation it also checks imported standard widget
strings. Tests: `i18n_checks::tests`, `i18n::tests::runtime_catalog_contains_every_translation`.

## PO rules

- Keep message contexts unchanged.
- Placeholders may be reordered with `{0}`, `{1}`… even if the source uses `{}`;
  keep every argument and its count. `{n}` is the plural count.
- Translate whole messages with their arguments; do not concatenate fragments
  or depend on leading/trailing spaces.
- Multiline entries start with `msgstr ""` (or `msgstr[N] ""`) followed by
  quoted continuation lines; replace all continuation lines when editing.
- Each catalog declares its own `Plural-Forms`; the matching runtime rules are in
  `src/i18n.rs`.
- Words legitimately equal to English may stay identical.

Russian/Spanish terminology: Key — Клавиша / Tecla; Rule — Правило / Regla;
Layer — Слой / Capa; Mapper — Маппер / Mapeador; Tap action — Действие при
нажатии / Acción al pulsar; Hold action — Действие при удержании / Acción al
mantener pulsado. Keep "Keymap" (user mapping) distinct from the system keyboard
layout.

The `small-window` example with `TECLOID_SMALL_LANGUAGE=qps-ploc` renders a
pseudo-locale (~40 % longer strings) to catch clipped text.

The Rules tab contains rules: each rule combines a Trigger field (a key or
combination) with actions and conditions. Use “rule” for the whole entry and
“trigger” for its input field (Russian: Правило / Триггер).
